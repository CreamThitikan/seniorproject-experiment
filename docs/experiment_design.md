# requirements

ภาพรวมการทดลอง
Research Problem
เมื่อผู้ใช้ยกเลิกการจองที่พักออนไลน์ ผู้ใช้ต้องการรู้ทั้งว่าตนจะได้เงินคืนหรือไม่ แต่ต้องรู้ด้วยว่าทำไมจึงได้ผลลัพธ์นั้น ตอนนี้เงินอยู่ที่ขั้นตอนใด และควรทำอย่างไรต่อ แพลตฟอร์มจึงต้องตัดสินใจว่าจะแสดงข้อมูล refund ในแต่ละขั้นตอนมากน้อยเพียงใด ข้อมูลที่น้อยเกินไปอาจทำให้ผู้ใช้เห็นแต่ผลลัพธ์โดยไม่รู้ที่มาที่ไป ต้องเดาเองหรือติดต่อ support ส่วนข้อมูลที่มากเกินไปอาจทำให้ผู้ใช้หาสิ่งที่ต้องการไม่เจอหรือต้องใช้เวลามากขึ้น อย่างไรก็ตาม ยังไม่ชัดเจนว่าปริมาณข้อมูลเท่าไรที่ทำให้ผู้ใช้รู้เหตุผลของสถานการณ์ตนเองได้ดีที่สุด และปริมาณข้อมูลที่ต่างกันส่งผลต่อการทำความเข้าใจในแต่ละขั้นตอนของกระบวนการ refund ต่างกันหรือไม่ งานนี้จึงศึกษาปัญหาดังกล่าวด้วยการทดลองจำลองแบบสำรวจ เพื่อให้ได้หลักฐานเบื้องต้นสำหรับการออกแบบการแสดงข้อมูล refund

Research Questions
RQ1: How does the amount of refund information affect users' difficulty of understanding of their refund situation?
RQ2: How does users' difficulty of understanding differ across information levels at each stage of the refund process?

ตัวแปรในการทดลอง
Information Level (ตัวแปรอิสระ)
L1 = ข้อมูลน้อย/จำกัด
L2 = ข้อมูลเพียงพอ/เหมาะสม
L3 = ข้อมูลมากเกินความจำเป็น
เป็น Between-subject Variable โดยผู้เข้าร่วมแต่ละคนเห็นเพียง 1 Level ตลอดการทดลอง
Stage (ตัวแปรภายในบุคคล)
Stage 1: Refund Eligibility
Stage 2: Refund Decision/Outcome
Stage 3: Refund Status
Stage 4: Refund Timing
ผู้เข้าร่วมทุกคนผ่านทั้ง 4 Stages จึงเป็น Within-subject Variable
Response Type (ตัวแปรหลักด้านความเข้าใจ)
หลังอ่านข้อมูลในแต่ละ Stage ผู้เข้าร่วมตอบคำถามเกี่ยวกับ เหตุผลหรือที่มาของผลลัพธ์ที่แสดง
แบ่งคำตอบเป็น
Correct Reason = สามารถระบุเหตุผลของผลลัพธ์ได้ถูกต้อง
Correctly Recognized Insufficient Information = รับรู้ได้ว่าข้อมูลที่ได้รับไม่เพียงพอที่จะระบุเหตุผล
Incorrect Reason = ระบุเหตุผลไม่ถูกต้อง
Unsure = ไม่แน่ใจ
Response Type เป็นข้อมูลหลักที่ใช้สะท้อน Understanding ตามนิยามของงานนี้ โดยพิจารณาว่าผู้ใช้สามารถเชื่อมโยง “ผลลัพธ์” กับ “เหตุผล” ได้หรือไม่
L1 มีข้อมูลเฉพาะผลลัพธ์แต่ไม่มีเหตุผล ดังนั้นคำตอบที่คาดหวังคือ Correctly Recognized Insufficient Information ซึ่งแสดงว่าผู้ใช้รับรู้ข้อจำกัดของข้อมูล แต่ ไม่ได้หมายความว่าผู้ใช้เข้าใจเหตุผลของสถานการณ์
L2/L3 มีข้อมูลเหตุผล ดังนั้น Correct Reason จึงสะท้อนว่าผู้ใช้สามารถเข้าใจที่มาของผลลัพธ์ได้
EC / Expected Correct
เป็นตัวแปรที่ใช้ตรวจว่า คำตอบของผู้เข้าร่วม ตรงกับคำตอบที่กำหนดไว้ล่วงหน้าตามเงื่อนไขของแต่ละ Level และ Stage หรือไม่
EC = 1 เมื่อเลือกคำตอบที่ผู้วิจัยกำหนดให้เป็นคำตอบที่ถูกต้องของ Level/Stage นั้น และ EC = 0 เมื่อเลือกคำตอบอื่น
ดังนั้น EC มีความหมายในด้าน ความถูกต้องของการทำ Task ไม่ใช่ตัววัด Understanding โดยตรง
ตัวอย่าง:
L1 → เลือก “หน้านี้ไม่ได้บอกเหตุผล” = EC 1 แต่ยัง ไม่ถือว่าเข้าใจเหตุผลของสถานการณ์
L2/L3 → เลือกเหตุผลที่ถูกต้อง = EC 1 และ สะท้อนว่าเข้าใจสถานการณ์
การเก็บ EC แยกจาก Response Type ทำให้สามารถตรวจสอบได้ทั้งว่า “ผู้ตอบทำ Task ตามเงื่อนไขได้หรือไม่” และ “คำตอบนั้นมีความหมายต่อ Understanding อย่างไร”
Task Completion Time
จับเวลาตั้งแต่ข้อมูลของแต่ละ Stage แสดงครบจนผู้เข้าร่วมส่งคำตอบ
บันทึกเป็นวินาที
ใช้สะท้อน Processing Effort / Efficiency ในการค้นหาและประมวลผลเหตุผลของผลลัพธ์
ใช้ร่วมกับ Response Type เพื่อดูว่าผู้ใช้ใช้เวลามากหรือน้อย และสุดท้ายสามารถระบุเหตุผลได้หรือไม่
Manipulation Check
ตรวจว่าผู้เข้าร่วมรับรู้ระดับปริมาณข้อมูลแตกต่างกันตามที่ออกแบบหรือไม่
ใช้ยืนยันว่า L1, L2 และ L3 สามารถทำหน้าที่เป็น Information Level ที่แตกต่างกันได้
Background Information
อายุ
ความถี่ในการจองที่พักออนไลน์
ประสบการณ์การขอ Refund
ความคุ้นเคยกับแพลตฟอร์มจองที่พักออนไลน์
อุปกรณ์ที่ใช้
ใช้อธิบายกลุ่มตัวอย่าง ตรวจสอบความสมดุลระหว่างกลุ่ม และพิจารณาประกอบการตีความเมื่อจำเป็น
ข้อกำหนด
ในการทดลองมีเฉพาะข้อมูลที่เกี่ยวข้องกับตัวแปรที่ศึกษา คือข้อมูลเรื่อง refund ไม่ใส่ภาพ รีวิว โฆษณา หรือเนื้อหาอื่นที่ไม่เกี่ยว
สิ่งเดียวที่เปลี่ยนระหว่างกลุ่มคือ ปริมาณ/เนื้อหาข้อมูล ส่วน scenario, reservation, เหตุการณ์, UI, จำนวนขั้นตอน, typography, visual hierarchy และ interaction เหมือนกันทุกกลุ่ม
ทุก level มี core fact (ข้อมูลที่เป็นคำตอบของคำถามใน stage นั้น) เหมือนกัน และอยู่ตำแหน่งเดียวกัน สิ่งที่ต่างคือบริบท เหตุผล และรายละเอียดรอบ ๆ
การทดลองนี้ต้องการลดภาระผู้เข้าร่วมให้มากที่สุด ผู้ตอบ ไม่ต้อง ทำสิ่งต่อไปนี้ในทุก level 
บวก ลบ คูณ หาร หรือหาเปอร์เซ็นต์ของจำนวนเงิน
บวกลบวัน นับวัน หรือนับวันทำการ
เทียบวันที่เพื่อหาว่าตัวเองอยู่ในช่วงไหนของนโยบาย
แปลงสกุลเงินหรือเวลา
ตีความเงื่อนไขซ้อนกันหลายชั้น
ทุกผลลัพธ์ที่ผู้ตอบต้องใช้ตอบคำถาม ระบบแสดงให้เสร็จแล้ว
ไม่ทำให้ผู้ตอบรู้สึกว่ากำลังทำข้อสอบ บอกผู้ตอบในตอนเริ่มว่าไม่ใช่ข้อสอบ ไม่แสดงผลถูก/ผิด คำถามใช้ภาษาธรรมชาติ และมีตัวเลือก "ดูจากหน้านี้แล้วไม่แน่ใจ" ทุกข้อ
ไม่มี interaction เพิ่มใน level ใด: ไม่มี accordion, tab, ลิงก์ "ดูเพิ่มเติม" ทุกอย่างแสดงในหน้าเดียว
ข้อมูลเสริมของ stage หนึ่งต้องไม่เฉลยคำตอบของ stage อื่น และไม่ซ้ำกับข้อมูลเสริมของ stage อื่น
ข้อมูลทุกรายการต้องถูกต้องและไม่ขัดแย้งกัน ทั้งในหน้าเดียวกันและข้ามหน้า
รูปแบบการทดลอง
Between-subject แบ่งผู้เข้าร่วมแบบสุ่มเป็น 3 กลุ่ม: กลุ่ม 1 = L1, กลุ่ม 2 = L2, กลุ่ม 3 = L3
ผู้เข้าร่วมแต่ละคนเห็น level เดียวตลอด ไม่รู้ว่ามีกลุ่มอื่น เพื่อไม่ให้ผู้ตอบรู้ตัวว่าแบบทดสอบกำลังวัดอะไร
ทุกคนผ่าน 4 stages เรียงตามเวลาในเรื่องเหมือนกัน (Eligibility → Decision → Status → Timing)
ใน 1 stage: ดูหน้าจอ + ตอบ 1 คำถาม
ใช้เวลาโดยรวมประมาณ 4–6 นาที
ขนาดตัวอย่าง: อย่างน้อยประมาณ 30 คนต่อกลุ่ม

นิยาม Information Level (L1, L2, L3)
สัดส่วนปริมาณข้อมูลโดยประมาณ L1:L2:L3 = 1:2.5:5


| Level | นิยาม | ผู้ตอบควรรู้สึกอย่างไร |
|---|---|---|
| L1 (น้อย/จำกัด) | มีเฉพาะ core fact ไม่มีเหตุผล เงื่อนไข หรือรายละเอียดประกอบ | รู้ผลลัพธ์ แต่ยังไม่รู้ว่าทำไมถึงเป็นแบบนี้ ยังไม่เห็นภาพรวม ข้อมูลน้อยไป |
| L2 (เพียงพอ) | core fact + ข้อมูลที่จำเป็นต่อการเข้าใจสถานการณ์และตอบคำถามได้สมเหตุสมผล เช่น เหตุผล จำนวนเงิน ช่องทาง วันที่ ผู้ดำเนินการ และตารางสรุปนโยบาย | รู้ผลและเหตุผล เห็นภาพรวม ไม่จำเป็นต้องหาอะไรเพิ่ม |
| L3 (มากเกิน) | ข้อมูลทั้งหมดของ L2 + ข้อมูลที่ ถูกต้อง เกี่ยวกับ refund แต่ไม่จำเป็น ต่อการตอบคำถาม เช่น นโยบายการคืนเงินที่ไม่เกี่ยวข้องกับเหตุการณ์นี้ | ได้ข้อมูลมาก มีเรื่องที่ไม่ได้ต้องใช้ในสถานการณ์นี้ ต้องคัดข้อมูลเอง |

เกณฑ์ของข้อมูลที่เพิ่มมาใน L2 และ L3
เกณฑ์ข้อมูลที่เพิ่มจาก L1 เป็น L2
ช่วยตอบคำถามพื้นฐานบอกเหตุผลของผลลัพธ์ของ stage นั้น
ไม่มีการคำนวณ
ไม่สร้างการกระทำใหม่ให้ผู้ตอบ เช่น ปุ่มใหม่ ลิงก์เพิ่มเติม

เกณฑ์ข้อมูลที่เพิ่มจาก L2 เป็น L3

รูปแบบการจัดข้อมูลเหมือน L2 
เกี่ยวข้องกับการขอคืนเงิน 
ไม่จำเป็นต่อการตอบคำถามของ stage นั้นหรือไม่เกี่ยวข้องกับสถานการณ์นี้ เช่น นโยบายการคืนเงินเมื่อเกิดเหตุสุดวิสัย ซึ่งไม่เกี่ยวข้องกับสถานการณ์จำลองนี้
ไม่มีข้อมูลที่เฉลยคำตอบของ stage อื่น
ไม่สร้างการกระทำใหม่
ไม่ทำให้ต้องคำนวณหรือตีความเงื่อนไขซ้อน

*สิ่งที่ห้ามใช้เป็นข้อมูลเพิ่มใน L3: ข้อมูลสุ่มหรือไม่เกี่ยวกับ refund (โปรโมชัน รีวิว สถานที่ท่องเที่ยว), ข้อความ policy ยาว, ข้อมูลที่ผิดหรือขัดกัน, ลิงก์หรือปุ่มใหม่, เงื่อนไขซับซ้อนที่ต้องตีความ

หลักการในการตั้งคำถาม
ถามเหตุผล ไม่ถาม core fact: "ความเข้าใจ" ซึ่งหมายถึงรู้ที่มาของผลลัพธ์ ไม่ใช่รู้แค่ผลลัพธ์ ถ้าถาม core fact ซึ่งมีครบทุก level หน้าที่สั้นที่สุด (L1) จะตอบได้เร็วที่สุดและทุกกลุ่มตอบถูก คำถามจึงวัดแค่ปริมาณที่ต้องอ่าน ไม่ได้วัดความเข้าใจ ส่วนเหตุผลคือข้อมูลที่ปริมาณต่างกันจริง (L1 ไม่มี, L2 มีพอดี, L3 มีท่ามกลางข้อมูลเสริม)
ถ้าถาม core fact ตรงๆ เช่น ได้เงินคืนเท่าไร ซึ่งเป็นข้อมูลที่ L1 มีอยู่แล้ว มีแนวโน้มที่ระยะเวลาในการตอบ L1 อาจน้อยสุด เพราะไม่มีข้อมูลอื่นมารบกวน หาง่าย
คำตอบที่ถูกขึ้นกับสิ่งที่หน้าจอแสดง: L1 = "หน้านี้ไม่ได้บอกเหตุผล", L2/L3 = เหตุผลที่ระบุไว้ เพื่อไม่ให้ผู้ตอบ L1 ได้คะแนนจากการเดาหรือความรู้เดิม และเพื่อแยกคนที่ตอบตามหน้าจอออกจากคนที่ตอบเกินข้อมูล

นำคำตอบของแต่ละ Stage มาจัดเป็น Response Type
กำหนด EC = 1/0 ตามคำตอบที่กำหนดไว้สำหรับแต่ละ Level
เก็บทั้ง Response Type และ EC แยกกัน เนื่องจากทั้งสองตัวมีความหมายต่างกัน
เตรียม Task Completion Time ของแต่ละ Stage
ตัวอย่าง
| ตัวเลือกที่เลือก | L1 | L2/L3 |
|---|---|---|
| A เหตุผลที่ถูก | ตอบเกินข้อมูล (บังเอิญตรง) (EC = 0) | ตอบตามหน้าจอ (EC = 1) |
| B/C เหตุผลที่ผิด | ตอบเกินข้อมูล + ผิด (EC = 0) | เข้าใจผิด (EC = 0) |
| D หน้านี้ไม่ได้บอกเหตุผล | ตอบตามหน้าจอ (EC = 1) | หาไม่เจอ (EC = 0) |



3: ตรวจสอบข้อมูลเบื้องต้น
ดูจำนวนผู้เข้าร่วมในแต่ละ Level
ตรวจสอบการกระจายของ Response Type
ดูสัดส่วน EC
ดู Task Completion Time ในแต่ละ Level และ Stage
เปรียบเทียบข้อมูลเบื้องต้นระหว่างกลุ่มเพื่อดูว่ามีความแตกต่างที่ผิดปกติหรือไม่
4: ตรวจสอบ Manipulation
ตรวจว่าผู้เข้าร่วมรับรู้ปริมาณข้อมูลของ L1, L2 และ L3 แตกต่างกันตามที่ออกแบบ
หาก Manipulation ไม่เป็นไปตามที่ตั้งใจ จะต้องระบุเป็นข้อจำกัดก่อนจะตีความผลหลัก
5: วิเคราะห์ Understanding จาก Response Type
ใช้ Response Type เป็นข้อมูลหลักในการตอบว่า ผู้ใช้เข้าใจสถานการณ์หรือไม่
พิจารณาสัดส่วนของแต่ละประเภทคำตอบใน L1/L2/L3
วิเคราะห์ว่าผู้ใช้สามารถระบุเหตุผลของผลลัพธ์ได้มากน้อยเพียงใด
สำหรับ L1 ให้พิจารณาเป็นกรณีที่ผู้ใช้ รับรู้ว่าข้อมูลไม่เพียงพอ แต่ยังไม่สามารถเข้าใจเหตุผลของผลลัพธ์
สำหรับ L2/L3 ให้พิจารณาว่าผู้ใช้สามารถระบุเหตุผลได้ถูกต้องหรือไม่
ใช้รูปแบบของ Response Type เพื่อแสดงทั้ง ความเข้าใจ ความเข้าใจผิด และการไม่สามารถระบุเหตุผลได้
6: วิเคราะห์ Task Success / EC
ใช้ EC เพื่อดูว่าผู้เข้าร่วมสามารถตอบ Task ตามคำตอบที่กำหนดไว้ได้หรือไม่
เปรียบเทียบ EC ระหว่าง L1/L2/L3 ทั้งในภาพรวมและแยกตาม Stage
EC ใช้เป็นข้อมูลด้าน Task Performance ไม่ใช่ตัวแทนของ Understanding
หมายความว่า EC ของ L1 สามารถเป็น 1 แม้ผู้ใช้จะยังไม่เข้าใจเหตุผล เพราะคำตอบที่ถูกของ L1 คือการรับรู้ว่าข้อมูลไม่เพียงพอหมายถึงว่าผู้ตอบยังไม่เข้าใจสถานการณ์มากพอ
7: วิเคราะห์ Task Completion Time
เปรียบเทียบเวลาที่ใช้ในการทำ Task ระหว่าง L1/L2/L3
วิเคราะห์ทั้งภาพรวมและแยกตาม Stage
พิจารณาเวลา ร่วมกับ Response Type เพื่อแยกว่าผู้ใช้ใช้เวลานานแล้วสามารถหาเหตุผลเจอ หรือใช้เวลานานแต่ยังไม่สามารถระบุเหตุผลได้
ใช้เวลาเป็นตัวชี้วัดด้าน Processing Effort / Efficiency ไม่ตีความว่าเวลาเพียงอย่างเดียวเท่ากับ Understanding
8: วิเคราะห์ผู้ที่ EC = 0
ไม่ตัดข้อมูลออก แต่ตรวจสอบว่า EC = 0 เกิดจาก Response Type ใด
ดูว่าเกิดมากใน Level หรือ Stage ใด
พิจารณาว่าผู้ที่ EC = 0 ใช้เวลามากหรือน้อยเมื่อเทียบกับผู้ที่ EC = 1
ใช้เพื่ออธิบายรูปแบบของการตอบที่ไม่เป็นไปตามข้อมูลบนหน้าจอ เช่น
เลือกเหตุผลที่ข้อมูลไม่ได้สนับสนุน
ตีความข้อมูลผิด
ไม่แน่ใจ
อาจใช้ผลส่วนนี้เป็น Supporting Analysis / Discussion เพื่ออธิบายว่าความแตกต่างของ Information Level อาจนำไปสู่รูปแบบความเข้าใจผิดแบบใด
9: วิเคราะห์ตาม Research Questions
RQ1: How does the amount of refund information affect users' understanding of their refund situation?
ใช้ Response Type เป็นตัวสะท้อนลักษณะของ Understanding
L1: หากตอบ “ข้อมูลในหน้านี้ไม่ระบุเหตุผล” ถือว่าเป็นคำตอบที่สอดคล้องกับข้อมูลที่ได้รับ แต่สะท้อนว่า ผู้ใช้ยังไม่สามารถเข้าใจเหตุผลของผลลัพธ์ได้
L2/L3: หากสามารถระบุเหตุผลของผลลัพธ์ได้ถูกต้อง จึงถือว่า ผู้ใช้สามารถเข้าใจสถานการณ์ได้
ใช้ EC เพื่อตรวจสอบว่าผู้เข้าร่วมตอบสอดคล้องกับคำตอบที่คาดไว้ของแต่ละ Level หรือไม่
สำหรับ Task Completion Time จะวิเคราะห์เฉพาะผู้ที่ EC = 1 เพื่อให้เวลาเป็นตัวแทนของระยะเวลาที่ใช้ในการทำ Task ได้สำเร็จตามเกณฑ์ที่กำหนด
เปรียบเทียบ Task Completion Time ระหว่าง L1, L2 และ L3 เพื่อดูว่าปริมาณข้อมูลต่างกันสัมพันธ์กับเวลาในการค้นหาและประมวลผลคำตอบอย่างไร
พิจารณา Response Type ประกอบกับเวลา เพื่อแยกความหมายของแต่ละ Level เช่น
L1: ใช้เวลาในการตรวจสอบและตัดสินว่าข้อมูลไม่เพียงพอ
L2/L3: ใช้เวลาในการค้นหาและระบุเหตุผลที่อธิบายผลลัพธ์
ตัวอย่างการตีความ
| Level | ลักษณะคำตอบที่พบบ่อย | Median Task Time (EC = 1) |
|---|---|---|
| L1 | ไม่พบเหตุผลในหน้า | 24 sec |
| L2 | ระบุเหตุผลได้ถูกต้อง | 10 sec |
| L3 | ระบุเหตุผลได้ถูกต้อง | 17 sec |
สามารถอภิปรายได้ว่า L1 ใช้เวลาในการทำ Task มากกว่า L2 แม้ผู้ตอบสามารถระบุได้ว่าหน้าไม่มีข้อมูลเหตุผล ขณะที่ L2 มีข้อมูลที่จำเป็นต่อการอธิบายผลลัพธ์จึงสามารถระบุเหตุผลได้รวดเร็วกว่า และ L3 แม้ยังสามารถระบุเหตุผลได้ แต่มีข้อมูลเพิ่มเติมที่ต้องอ่านและพิจารณามากขึ้น จึงอาจใช้เวลามากกว่า L2
ดังนั้น การตอบ RQ1 จะพิจารณา Understanding จาก Response Type และใช้ Task Completion Time ของ EC = 1 เป็นข้อมูลด้าน efficiency/processing effort ประกอบ ไม่ใช้ Task Time เป็นตัววัด Understanding โดยตรง
RQ2: How does users' understanding differ across information levels at each stage of the refund process?
วิเคราะห์แยก Stage 1–4
ในแต่ละ Stage เปรียบเทียบ Response Type ของ L1/L2/L3 เพื่อดูว่าผู้ใช้สามารถระบุเหตุผลของผลลัพธ์ได้แตกต่างกันอย่างไร
เปรียบเทียบ Task Completion Time เฉพาะ EC = 1 ระหว่าง L1/L2/L3 ในแต่ละ Stage
พิจารณาว่า Stage ใดมีความแตกต่างของเวลาและรูปแบบ Response Type ระหว่าง Information Level มากหรือน้อยที่สุด
นำผลของ Response Type และ Task Time มาพิจารณาร่วมกันเพื่อระบุว่าขั้นตอนใดได้รับผลจาก Information Level ชัดเจนที่สุด
ตัวอย่างผลสมมติ
| Stage | L1 | L2 | L3 |
|---|---|---|---|
| Eligibility | 22 sec | 10 sec | 15 sec |
| Decision | 18 sec | 11 sec | 14 sec |
| Status | 31 sec | 12 sec | 22 sec |
| Timing | 20 sec | 13 sec | 16 sec |
หาก Stage 3 มีความแตกต่างระหว่าง L1/L2/L3 มากที่สุด และในขณะเดียวกัน L1 มีสัดส่วนผู้ที่ไม่สามารถระบุเหตุผลได้สูงกว่า L2/L3 อาจอภิปรายได้ว่า Refund Status เป็นขั้นตอนที่ระดับข้อมูลมีความสำคัญต่อการทำความเข้าใจสถานการณ์มากกว่าขั้นตอนอื่น

*** การจัดการข้อมูล EC = 0
ข้อมูลที่ EC = 0 จะไม่ถูกใช้เป็นข้อมูลหลักในการเปรียบเทียบ Task Completion Time เพื่อ RQ1/RQ2 แต่จะเก็บไว้เป็น Supporting Analysis / Discussion
พิจารณาเพิ่มเติมว่า:
EC = 0 เกิดใน Level ใดและ Stage ใดมากที่สุด
ผู้ตอบผิดเลือกเหตุผลประเภทใด
เกิดการตอบ “ไม่แน่ใจ” มากน้อยเพียงใด
ผู้ที่ EC = 0 ใช้เวลามากหรือน้อยเมื่อเทียบกับผู้ที่ EC = 1
รูปแบบความผิดพลาดอาจสะท้อนปัญหาในการตีความข้อมูลหรือการเชื่อมโยงผลลัพธ์กับเหตุผลอย่างไร
ตัวอย่าง หาก L3 มี EC = 0 บางส่วนและผู้ตอบกลุ่มนี้ใช้เวลานานกว่าผู้ที่ตอบถูก อาจนำไปอภิปรายเพิ่มเติมได้ว่า การเพิ่มข้อมูลอาจทำให้เกิดความยากในการคัดเลือกข้อมูลที่เกี่ยวข้องสำหรับผู้ใช้บางส่วน แต่จะไม่นำผลดังกล่าวมาเป็นข้อสรุปหลักของ RQ หากจำนวนข้อมูลไม่เพียงพอ

ข้อจำกัด
ข้อมูลและแพลตฟอร์มเป็นข้อมูลสมมติทั้งหมด 
ลดรูปกระบวนการ (แยกเป็น 4 หน้าจอ, อนุมัติอัตโนมัติ, นโยบายเดียว, ผลเดียวคือคืนบางส่วน) จึงไม่ครอบคลุมการปฏิเสธ คืนเต็ม เครดิต หรือการส่งเอกสาร
ผู้ตอบสวมบทบาท ไม่มีเงินจริงหรือความกังวลจริง ความตั้งใจอ่านอาจต่างจากคนที่รอเงินอยู่
ผู้ตอบเห็นทีละหน้า ไม่มีการค้นหา กดไปหน้าอื่น หรือดูช่องทางอื่น เช่น อีเมล แชท
ใช้ scenario เดียวและกลุ่มตัวอย่างเดียว (ภาษาไทย สกุลเงินบาท) สรุปไปยังกรณีหรือประชากรอื่นไม่ได้
เหตุผลและข้อมูลที่ถามเป็นสิ่งที่ผู้ศึกษากำหนด ผู้ใช้จริงอาจไม่ต้องการเหตุผลเหล่านี้ หรือต้องการมากกว่านั้น (รายละเอียดนโยบาย ทางเลือก การอุทธรณ์ ผู้รับผิดชอบ) ระดับ L2 "เหมาะสม" จึงหมายถึงพอสำหรับคำถามที่เราตั้ง ไม่ใช่พอสำหรับความต้องการจริงของผู้ใช้ และงานนี้ไม่ได้วัดความต้องการข้อมูลโดยตรง
ความเข้าใจวัดด้วยการเลือกตัวเลือก จึงวัดได้แค่ว่าระบุข้อมูลที่ปรากฏในหน้าได้หรือไม่ ไม่ใช่ความเข้าใจเชิงลึกหรือการตัดสินใจต่อ
ไม่ได้วัดความรู้สึก ผู้ตอบออาจจะเข้าใจแต่ไม่สบายใจ 
เวลาไม่เท่ากับความยาก เพราะขึ้นกับความเร็วอ่านและสมาธิ และงานของ L1 (ยืนยันว่าไม่มี) ต่างชนิดจากงานของ L2/L3 (หาให้เจอ)
ตัวเลือกออกแบบโดยผู้ศึกษา บางข้อ (อีเมลยืนยัน ติดต่อ Support) คนเดาถูกได้จากประสบการณ์ ทำให้ L1 ตอบเกินข้อมูลสูงโดยธรรมชาติ และตัวเลือก "ในหน้านี้ไม่ได้บอก" อาจถูกเลือกเพราะไม่อยากหาต่อ
ลำดับ stage ตายตัว และผู้ตอบอาจเรียนรู้ข้าม stage (เช่น L1 รู้ว่าหน้าไม่บอกเหตุผล)
