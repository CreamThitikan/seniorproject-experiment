# StayBook — เว็บทดลองการอ่านข้อมูลการคืนเงิน

เว็บ static (HTML + vanilla JS) สำหรับ GitHub Pages ใช้ Google Apps Script ที่ผูกกับ Google Sheets เป็น backend

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าตา UI และ CSS (จาก prototype เดิม) |
| `app.js` | เนื้อหา L1/L2/L3, การแสดงผล, สุ่มกลุ่ม, จับเวลา, ส่งข้อมูล, resume, โหมด dev/mock |
| `config.js` | URL ของ Apps Script (`APPS_SCRIPT_URL`) |
| `apps-script/Code.gs` | backend: สุ่มกลุ่ม, บันทึกข้อมูล, คำนวณ EC และ response_type |
| `docs/experiment_design.md` | สำเนาเอกสารออกแบบการทดลองจาก Google Doc |
| `tests/` | ทดสอบ Code.gs และ server จำลองสำหรับทดสอบในเครื่อง |

---

## 1. ตั้งค่า Google Sheets และ Apps Script

1. สร้าง Google Sheet ใหม่ (เช่นชื่อ `StayBook data`)
2. เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. ลบโค้ดเดิมใน `Code.gs` แล้ววางเนื้อหาทั้งหมดจาก `apps-script/Code.gs` กดบันทึก
4. เลือกฟังก์ชัน `setup` ในแถบด้านบน แล้วกด **Run**
   - ครั้งแรก Google จะขอสิทธิ์ ให้กดอนุญาต (ถ้าขึ้น "Google hasn't verified this app" ให้กด Advanced → Go to ... (unsafe) เพราะเป็นสคริปต์ของเราเอง)
   - จะได้แท็บ `Participants`, `Responses`, `Config` (เรียก `setup` ซ้ำได้ ไม่ลบข้อมูลเดิม)
5. เลือกฟังก์ชัน `selfTest` แล้วกด **Run** — ใน Execution log ต้องเห็น `selfTest passed`
6. กด **Deploy → New deployment**
   - Select type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** (ผู้เข้าร่วมไม่ต้องล็อกอิน)
   - กด Deploy แล้วคัดลอก **Web app URL** (ลงท้ายด้วย `/exec`)
7. เปิด URL นั้นในเบราว์เซอร์ ต้องเห็น `{"ok":true}`
8. ถ้าเคย deploy เวอร์ชันก่อนหน้า (ที่ใช้ UUID) แนะนำให้รัน `setup()` อีกครั้งหลังวางโค้ดใหม่ เพื่อเพิ่มตัวนับ `participant_seq` ใน Config และตั้งคอลัมน์ `participant_id` ทั้งคอลัมน์เป็นข้อความ (ถึงไม่รัน โค้ดก็สร้างตัวนับและตั้งรูปแบบข้อความให้แถวใหม่เอง)
9. ใน Google Sheet: **File → Settings → Time zone** ตั้งเป็น `(GMT+07:00) Bangkok` เพื่อให้ `started_at` / `submitted_at` แสดงเวลาไทย

**เมื่อแก้ Code.gs ภายหลัง** ต้องไปที่ **Deploy → Manage deployments → ✏️ Edit → Version: New version → Deploy** ไม่อย่างนั้นเว็บจะยังเรียกโค้ดเวอร์ชันเก่า (URL เดิมใช้ต่อได้)

### ฟังก์ชันที่รันเองจาก editor

| ฟังก์ชัน | ใช้เมื่อ |
|---|---|
| `setup()` | ครั้งแรก หรือเมื่อแท็บหาย |
| `selfTest()` | ตรวจตารางคำตอบที่ถูกและการคำนวณ EC |
| `resetCounter()` | รีเซ็ตตัวนับสุ่มกลุ่มและเลขผู้เข้าร่วม (ทั้งของจริงและทดสอบ) เป็น 0 — คนถัดไปได้ L1 และเลขที่ว่างตัวแรก (ถ้ายังมีแถว 001–005 ในชีต จะได้ 006 เพื่อไม่ให้เลขซ้ำ ถ้าลบแถวเหล่านั้นแล้วจะเริ่มที่ 001) — **ห้ามรันระหว่างเก็บข้อมูลจริง** |

## 3. Deploy บน GitHub Pages

1. สร้าง repository บน GitHub แล้ว push โฟลเดอร์นี้ขึ้นไป
2. ใน repo: **Settings → Pages → Build and deployment**
   - Source: **Deploy from a branch**
   - Branch: `main` และโฟลเดอร์ `/ (root)` → Save
3. รอ 1–2 นาที จะได้ URL แบบ `https://<username>.github.io/<repo>/`

> หมายเหตุ: GitHub Pages แบบฟรีต้องเป็น repo สาธารณะ ไฟล์ทุกไฟล์ (รวม `docs/` และ `apps-script/Code.gs` ที่มีคำตอบที่ถูก) จะเปิดอ่านได้จากเว็บ ถ้าไม่ต้องการ ให้ย้าย `docs/` และ `tests/` ไปเก็บที่อื่นก่อนเปิดใช้จริง

## 4. ลิงก์ที่ใช้

| ลิงก์ | ใช้ทำอะไร |
|---|---|
| `https://.../` | **ลิงก์สำหรับผู้เข้าร่วม** ไม่เห็นแถบผู้วิจัย |
| `https://.../?dev=1` | ทดสอบกับชีตจริง ข้อมูลถูกบันทึกเป็น `is_test=TRUE` ได้เลขผู้เข้าร่วมแบบ `T001`, `T002`, ... และใช้ตัวนับแยก (`test_counter`, `test_participant_seq`) จึงไม่ทำให้การสุ่มและเลขของจริงเพี้ยน แถบผู้วิจัยใช้สลับ level / กระโดดไปหน้าใดก็ได้ |
| `https://.../?dev=1&mock=1` | ไม่เรียกเครือข่ายเลย ใช้ backend จำลองในหน้าเว็บ (ข้อมูลอยู่ใน `localStorage` ของเบราว์เซอร์) |
| `https://.../?dev=1&mock=1&fail=1` | จำลองว่าเน็ตหลุดทุกครั้ง ใช้ดูหน้าลองใหม่และคิวที่ค้างส่ง |

ในโหมด dev แถบผู้วิจัยจะแสดง ID ย่อ, level, และจำนวนรายการที่ค้างส่ง เปิด Console (F12) จะเห็น log การส่งข้อมูล และพิมพ์ `staybookDebug.mockDb()` เพื่อดูข้อมูลของโหมด mock ได้

## 5. วิธีทดสอบ

### 5.1 ทดสอบ Code.gs ในเครื่อง (ต้องมี Node.js)

```bash
node tests/apps-script.test.js
```

ต้องจบด้วย `ALL PASSED` — ทดสอบการวนกลุ่ม L1→L2→L3, ตัวนับแยกของการทดสอบ, การกันข้อมูลซ้ำ, EC/response_type, การปฏิเสธค่าที่ไม่ถูกต้อง และการกัน formula injection

### 5.2 ทดสอบทั้งระบบในเครื่องโดยไม่ต้อง deploy

```bash
node tests/local-server.js
```

เปิด `http://localhost:8000/` เว็บจะคุยกับ server จำลองที่รัน `Code.gs` ตัวจริง

- ดูข้อมูลในชีตจำลอง: `http://localhost:8787/sheets`
- จำลองเน็ตหลุด: `http://localhost:8787/fail?on=1` (ปิดด้วย `?on=0`)
- จำลองเซิร์ฟเวอร์ช้า: `DELAY_MS=3000 node tests/local-server.js`

### 5.3 สิ่งที่ควรลองด้วยมือ (กับ `?dev=1` บนชีตจริงก่อนเก็บข้อมูล)

1. **สุ่มกลุ่ม**: เริ่มใหม่ 3 ครั้ง (ใช้แท็บใหม่ทุกครั้ง) → แท็บ `Participants` ได้ L1, L2, L3 ตามลำดับ ได้เลข T001, T002, T003 และแท็บ `Config` เพิ่มเฉพาะ `test_counter` กับ `test_participant_seq`
2. **กดซ้ำ**: กด "ส่งคำตอบ" รัว ๆ → `Responses` มี 1 แถวต่อ stage
3. **รีเฟรช**: รีเฟรชกลาง stage 2 → กลับมาที่ stage 2 ด้วย level เดิม แถว stage 2 เป็นต้นไปมี `resumed=TRUE` และไม่มีผู้เข้าร่วมแถวใหม่
4. **เน็ตหลุด**: DevTools → Network → Offline แล้วตอบ 1–2 stage → ผู้เข้าร่วมไปต่อได้ตามปกติ ไม่เห็น error, แถบผู้วิจัยแสดง "ค้างส่ง n" → เปลี่ยนกลับเป็น Online → ข้อมูลเข้าชีตครบ
5. **ซ่อนแท็บ**: ระหว่าง stage สลับไปแท็บอื่น 10 วินาที → `hidden_ms` ประมาณ 10000
6. **มือถือ**: เปิดบนมือถือจริงอย่างน้อย iOS Safari และ Android Chrome
7. **ลิงก์ผู้เข้าร่วม**: เปิดลิงก์ปกติ → ต้องไม่เห็นแถบผู้วิจัย

### ก่อนเริ่มเก็บข้อมูลจริง

- [ ] รัน `resetCounter()` หนึ่งครั้ง (ผู้เข้าร่วมจริงคนแรกจะได้ L1)
- [ ] จะลบแถวทดสอบออกหรือไม่ก็ได้ ตอนวิเคราะห์ให้กรอง `is_test = FALSE`
- [ ] ทดสอบลิงก์ผู้เข้าร่วมจริงบนมือถือ 1 รอบ (รอบนี้จะนับเป็นข้อมูลจริง ให้ลบแถวนั้นทิ้งและรัน `resetCounter()` อีกครั้ง)

## 6. ข้อมูลที่บันทึก

**Participants** — หนึ่งแถวต่อผู้เข้าร่วม

| คอลัมน์ | ความหมาย |
|---|---|
| `participant_id` | เลขรันที่เซิร์ฟเวอร์ออกให้: `001`, `002`, ... (เกิน 999 เป็น `1000`, ...) ข้อมูลทดสอบเป็น `T001`, ... ไม่ผูกกับตัวบุคคล |
| `assigned_level` | L1 / L2 / L3 ที่เซิร์ฟเวอร์กำหนด |
| `started_at` | เวลาที่กดเริ่ม (เวลาเซิร์ฟเวอร์) |
| `age_range`, `booked_before`, `cancel_experience` | ข้อความตัวเลือกคำถามพื้นฐาน |
| `manipulation_check` | 1–5 |
| `completed`, `completed_at` | TRUE เมื่อตอบคำถามสุดท้ายแล้ว |
| `is_test` | TRUE เมื่อมาจาก `?dev=1` |

**Responses** — หนึ่งแถวต่อ stage

| คอลัมน์ | ความหมาย |
|---|---|
| `level` | level ที่ใช้แสดง (ผู้เข้าร่วมจริงใช้ `assigned_level` เสมอ) |
| `stage` | 1–4 |
| `option_index` / `option_label` / `option_text` | 0–3 / A–D / ข้อความ (เซิร์ฟเวอร์เติมเอง) |
| `time_ms` | เวลาตั้งแต่ข้อมูลของ stage แสดงครบจนกดส่ง **รวม** เวลาที่แท็บถูกซ่อน |
| `hidden_ms` | ส่วนของ `time_ms` ที่แท็บถูกซ่อน (เวลาที่ดูจอจริง ≈ `time_ms − hidden_ms`) |
| `resumed` | TRUE ถ้าตอบ stage นี้หลังจากผู้เข้าร่วมรีเฟรชหน้า |
| `submitted_at` | เวลาเซิร์ฟเวอร์ที่ได้รับคำตอบ (ถ้าเน็ตหลุดอาจช้ากว่าเวลาที่กดจริง) |
| `expected_correct` | EC 1/0 |
| `response_type` | ตารางด้านล่าง |

| ตัวเลือกที่เลือก | L1 | L2/L3 |
|---|---|---|
| เหตุผลที่ถูก | ตอบเกินข้อมูล + ถูก (EC 0) | ตอบตามหน้าจอ (EC 1) |
| เหตุผลที่ผิด | ตอบเกินข้อมูล + ผิด (EC 0) | เข้าใจผิด (EC 0) |
| D ข้อมูลไม่เพียงพอ | ตอบตามหน้าจอ (EC 1) | หาไม่เจอ (EC 0) |

เหตุผลที่ถูกของแต่ละ stage อ้างอิงจากข้อความ: (1) ยกเลิกก่อนเช็คอิน 9 วัน (2) ส่งอีเมลยืนยัน (3) StayBook ส่งเงินแล้ว ตอนนี้รอธนาคารดำเนินการ (4) โทรติดต่อ StayBook

**ไม่เก็บ** ชื่อ อีเมล เบอร์โทร IP หรือข้อมูลอุปกรณ์ (Apps Script ไม่เห็น IP ของผู้เข้าร่วมอยู่แล้ว)

**ถ้าแก้ข้อความตัวเลือกใน `app.js`** ต้องแก้ `OPTIONS` / `CORRECT_TEXT` ใน `Code.gs` ให้ตรงกันแล้ว deploy เวอร์ชันใหม่ (และ `MOCK_CORRECT` ใน `app.js` ถ้าตำแหน่งคำตอบที่ถูกเปลี่ยน)
